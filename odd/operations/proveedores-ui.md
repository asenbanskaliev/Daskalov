## Selección de OpenRouter y NVIDIA Build desde la interfaz — 8 noviembre 2026

El selector `#provider` incluye `openrouter` y `nvidia`, además de Ollama local, Ollama Cloud y Demo. En un servidor **privado (loopback)**, seleccionar el proveedor, pegar la clave personal en el campo tipo password y pulsar **Aplicar clave**; la interfaz consulta el catálogo real, permite buscar por nombre y elegir modelo en la lista `#modelPicker`. El modelo elegido se puede corregir manualmente en `#model`.

Claves y privacidad: la clave de OpenRouter/NVIDIA se guarda exclusivamente en un `Map` en memoria JavaScript de la pestaña, nunca se escribe en `localStorage`, SQLite, URL ni cookies. Se envía por el header `x-daskalov-provider-key` al backend **del mismo origen**, que la reenvía por TLS únicamente al proveedor seleccionado y solo en esa petición. El botón **Olvidar clave** la elimina de memoria; al recargar se pierde. Se aconseja no compartir el navegador de una clase con claves activas y cerrar la pestaña al terminar. El usuario debe revisar cuotas y facturación reales de los proveedores. No se habilita a terceros ni menores sin autorización legal.

Endpoints oficiales fijos: OpenRouter `https://openrouter.ai/api/v1/models` y `/chat/completions`; NVIDIA `https://integrate.api.nvidia.com/v1/models` y `/chat/completions`. Si NVIDIA no ofrece el endpoint compatible de catálogo (404/405/501), se muestra una lista reducida de modelos publicada en su documentación; la disponibilidad real puede cambiar. No se aceptan URLs arbitrarias, y el modo Demo y los accesos públicos siguen prohibiendo todas las API de IA. Las respuestas en streaming son SSE compatibles con OpenAI y pasan por el filtro de seguridad del personaje como antes. No se exponen trazas de razonamiento.

Fuente OpenRouter: https://openrouter.ai/docs/api/api-reference/models/get-models ; NVIDIA: https://docs.api.nvidia.com/nim/reference/llm-apis .

### Catálogo y modelos gratuitos
OpenRouter muestra el catálogo completo, con filtro opcional **Solo modelos con sufijo `:free`**. Este sufijo identifica la oferta gratuita de OpenRouter; no implica disponibilidad ilimitada ni compatibilidad educativa garantizada. NVIDIA mantiene la selección de modelos disponibles en Build y su catálogo. La interfaz ofrece enlaces a https://openrouter.ai/settings/keys y https://build.nvidia.com/ para obtener credenciales propias. El listado se puede buscar y actualizar. La clave continúa limitada a la pestaña y al proveedor elegido.

### Prueba real opcional fuera del CI
No activar en PR ni GitHub Actions. En un terminal privado establecer `DASKALOV_REMOTE_SMOKE_CONSENT=1`, `DASKALOV_REMOTE_SMOKE_PROVIDER=openrouter` (o `nvidia`), `DASKALOV_REMOTE_SMOKE_MODEL=<id-de-modelo-real>` y `DASKALOV_REMOTE_SMOKE_KEY` con credencial personal fuera de archivos o repositorios. Ejecutar `npm run smoke:remote:local`. Primero comprueba el ID en el catálogo y, si existe, llama **una sola vez** al modelo con una frase sintética de saludo. El resultado solo da latencia y cantidad de caracteres. El proveedor puede cobrar por catálogo/consulta; comprobar cuotas y uso de datos. Se requiere autorización de adulto responsable antes de involucrar menores. El script nunca publica la respuesta, los errores ni la API key.

### Diferencia entre catálogo y modelo operativo
Una respuesta HTTP 200 a `/v1/models` **solo** prueba que el listado es accesible: no confirma que una inferencia vaya a funcionar. La UI presenta `Catálogo accesible (inferencia sin verificar)` para OpenRouter/NVIDIA. El smoke real con `NVIDIA_API_KEY` de Actions el 8 de noviembre obtuvo catálogo de 84 modelos, pero varios intentos de `/chat/completions` dieron 404/410. No declarar que los modelos de NVIDIA responden hasta conseguir un smoke real con texto final y streaming. Los costes de modelos remotos siguen siendo desconocidos sin factura.

### Seguridad posterior a las pruebas reales del 8 de noviembre
Se ejecutaron pruebas reales y limitadas contra NVIDIA con el secreto existente `NVIDIA_API_KEY` de Actions, sin exponerlo. El endpoint `GET /v1/models` devolvió **HTTP 200 con 84 identificadores**, pero `POST /v1/chat/completions` produjo HTTP **410/404** en varios modelos, por lo que no hay validación positiva de inferencia. Referencias de ejecución: 42482142465, 42482245297, 42482335851, 42482486255, 42482625031 y 42482778144. **El workflow se ha cambiado a manual en `main`, con Environment protegido**, para evitar que futuros pushes editables puedan reutilizar el secreto. Antes de volver a probarlo, el propietario debe configurar revisores del Environment `daskalov-cloud-test` y crear en él el secreto `DASKALOV_ENV_NVIDIA_API_KEY`; no poner esta clave en el repositorio ni en texto en el código. El acceso a la lista de modelos no valida disponibilidad de completions ni autoriza despliegue.

### Diagnóstico de permisos NVIDIA: modelos listados, pero chats 404/410
La documentación oficial de NGC establece que el rol **Public API Endpoints User** concede acceso a los endpoints de inferencia NIM. La clave personal solo puede habilitar ese servicio cuando la organización y el usuario disponen del rol. Referencia: https://docs.nvidia.com/ngc/latest/ngc-user-guide.html . En los foros oficiales otros usuarios han comunicado que `GET /v1/models` devuelve 200 mientras `POST /v1/chat/completions` responde 410 o 404 sin ese acceso: https://forums.developer.nvidia.com/t/request-to-enable-public-api-endpoints-http-410-on-chat-completions/386918 . Esto **no demuestra** que sea el origen del problema en esta cuenta, pero es la primera verificación. Acceder a la organización NGC, comprobar los permisos del servicio `Public API Endpoints` para usuario y clave y solicitar a NVIDIA la activación si falta; regenerar la clave tras corregir permisos y almacenarla exclusivamente en un Environment de Actions. No copiar el valor a issues, logs o conversaciones.
